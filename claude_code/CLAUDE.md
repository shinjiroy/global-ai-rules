## 共通設定

- 日本語で出力すること
- WebFetchの代わりにmcp__readability__read_url_content_as_markdownを使用する

## 全プロジェクト共通のルール

任意の、開発のプロジェクトについて以下を守ること

- 以下のケースを除き、コードを書く時はテストコードもセットで書くこと
  - Terraform等のIaC
  - ApacheやRDB等の設定ファイル
  - 単純なDto等のクラス
- 実行環境やTerraform等は全てDockerで準備すること
  - さらに、ローカルでの動作確認用としてdocker-compose.yamlを準備すること
- ファイルを作成する時は末尾に改行を入れること
- **ドキュメントの現在性**: 任意のドキュメントを書く際は、常に現在の状態を記述すること
  - 時系列的な表現（「新機能」「追加された」「今後」「最近追加された」など）を避ける
  - 機能の説明は現在の動作を記述する
  - 変更履歴が必要な場合は別のセクション（CHANGELOG、Git履歴など）に記載する
  - ドキュメントを読む人は「今この機能がどう動作するか」を知りたいのであって、「いつ追加されたか」や「これは新機能であるということ」は知る必要がない
  - 実装時の文脈（「今追加している」）をドキュメントに持ち込まない

## 高価格モデルでのオーケストレーション

上位・高価格モデルをオーケストレータにしてサブエージェントへ委任する場合の要点(詳細は `agent-orchestration` スキル):

- 実装は安価で有能なモデル(Sonnet等)、レビュー・分析は上位モデル(Opus等)に委任。レビューは実装者と別エージェントで独立性を確保する
- オーケストレータ(特に最上位モデル)のコンテキストは高価。長時間サブエージェントを `TaskOutput` の block=true でポーリングせず完了通知に任せ、生トランスクリプトを取り込まない
